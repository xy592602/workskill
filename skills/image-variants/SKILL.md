# 批量扩图

## 输入与计划
读取母版、权威文案列表、配色方案、版式方案和本轮数量。保持母版视觉语言。明确配色变化不等于结构变化；不同文案可复用已合格版式。
默认不启动历史总目标，按本轮授权数量执行。

使用 `scripts/build_manifest.py` 读取结构化计划，生成组合清单。命令：
```bash
python scripts/build_manifest.py plan.json manifest.json
```
计划结构见 `references/plan.example.json`。每张记录母版、配色、版式、完整文案与稳定文件名。工具只生成清单，不生成图片或调用收费API。

## 执行
1. 核对清单组合数：母版数×配色数×版式数×文案数。拒绝空输入、重复ID和超出本轮数量上限的计划。
2. 每批只执行用户授权的数量，已完成项先核验并复用，不因重启全部重跑。创建请求超时不能视为确认失败。
3. 换色时保留版式；换版时至少改变主要信息块结构、分区或阅读层级，不将轻微移动作为新布局。
4. 换文案时替换完整标题和正文。长度不兼容则换母版，不删减正文；每个变体以母版与该条文案为依据，不连续编辑上一个文案版本。
5. 对不可重绘资产预留空位，使用授权原件合成，避免再次送入模型造成改动。
6. 逐张检查文件能打开、尺寸正确、文本完整、风格一致、结构确有变化、没有资产重复。检查项分别记录，不用拼图抽样代表整批。
7. 单张明确失败允许最多两次定向修复；用新文件保存失败和修复版本关系。两次仍不合格标记待处理，不无限重试凑数。

## 状态
计划条目初始 `planned`；实际执行后分别记录 `generated`、`result_unknown` 或 `failed`。视觉质检和业务审核是独立字段；未审核不得标记通过。

## 执行与记录
使用当前环境已配置的图片生成或编辑工具，遵循该工具的调用说明。没有可用工具时只输出方案和未执行状态，不把提示词当作成图。记录实际工具、输入引用、输出路径和执行结果；不得记录密钥。请求结果未知时先找已有记录或产物，不盲目重复提交。

## 交付
交付文件、逐项质检结果、失败或待核实项。技术检查通过不等于业务审核通过；不虚构运行、审核、上传或交付记录。
